# Project conventions

## Code style

- Keep code clean and easy to modify.
- Keep comments to two lines or fewer, except docstrings.
- Prefer small, focused interfaces so policies, environments, and visualization
  code can evolve independently.

## CHPC execution

- Do not run simulator or GPU workloads on login nodes.
- Keep sensitive data on Redwood only.

## Writing style (deck, docs, figure labels)

- Declarative, timeless prose. No development history, no "we found".
- No em dashes anywhere. One symbol, one meaning across text and figures.
- Keep docs short and plain.
